定位与准备

第三章整合课，保留34–74分钟40分钟项目实施与记录。目标是学生自己编写、解释、测试一段含顺序、选择与迭代的程序。使用虚构分钟输入，不收集真实学习数据。此前已学运算、布尔、分支、嵌套、两类循环及随机，项目选最直接的固定三次循环，随机仅扩展。

英文投影、中文备注；N 打开备注，课堂问题先独立作答再展开答案。图解可聚焦放大。实验室 Chapter 3 Programming Lab 使用本章 AP 风格子集。每条语句独立一行，花括号独立成行；INPUT 队列每行一个 JSON 标量，数字直接写，字符串带双引号。屏幕逐条显示便于追踪；考场 DISPLAY 定义的空格分隔与显示界面换行不要混淆。

关键讲解、答案与诊断

需求合同：三个输入均为0到180之间整数，30及以上达标。达标显示Goal met并count+1，未达标显示Keep going。第三天后输出count，再按count≥2输出On track，否则Try again。程序假设有效输入，未实现验证；−1、181和字符串不属于本项目核心测试输入。每次运行重新初始化。

必测完整输出：29/30/31 → Keep going、Goal met、Goal met、2、On track；0/0/0 → Keep going三次、0、Try again；30/30/30 → Goal met三次、3、On track。可加180/29/0 → Goal met、Keep going、Keep going、1、Try again。AP DISPLAY参考定义以空格分隔，本实验室逐行展示不改变输出值与顺序。

第8页先预测再写代码；第10页保留预测，不把运行结果回填成“事前预期”。计数初始化放循环外；每轮INPUT与日分支放内；最终两项报告放外。一天未达标时count保持，不需要设置0。只测31无法辨别>和≥，30才是决定性反例。

教师参考实现（课堂先让学生独立完成）
count ← 0
REPEAT 3 TIMES
{
  minutes ← INPUT()
  IF(minutes ≥ 30)
  {
    DISPLAY("Goal met")
    count ← count + 1
  }
  ELSE
  {
    DISPLAY("Keep going")
  }
}
DISPLAY(count)
IF(count ≥ 2)
{
  DISPLAY("On track")
}
ELSE
{
  DISPLAY("Try again")
}

以上实现为参考之一，接受等价算法与清楚变量名，但输出、输入次数和边界须一致。不得把这份教师答案当作学生原创成果。随机扩展只在核心输出后附加鼓励，不改变已有判定；用RANDOM(1,2)选择两条允许消息，可记录范围性质而不要求某一次固定输出。

同伴角色：一人预测与读需求，另一人逐步解释代码，再交换。反馈应指向具体输入、语句或输出。保存自己的代码和原始测试；若自己无bug，允许对第15页给定错误片段制作修复记录并注明材料来源。教师模板、同伴建议或引用内容均保留归属说明。

常见错因与干预：count重置放内→三次30只得1；把>当≥→输入30错误；最终提示放内→出现多条过早总评；INPUT放外→三轮复用同一值；每天都+1→全0仍count3。分别用针对性测试，不仅检查一个正确输出。

评价与作业

12分形成性项目量表：输入恰3次且初始化正确0–2；日判定含30且消息/计数正确0–2；最终count与总判定正确0–2；三组预测和实际测试证据0–2；能解释边界与状态跟踪0–2；具体修改/复测及归属记录0–2。每项0无证据、1部分、2充分。建议≥9/12且修正边界与计数重置后进入后续内容；这是教师标准不是AP评分。

项目表链接：Chapter 3 Project Sheet。至少需代码、三组测试、一个具体算法解释和一项可核查修改记录。基础项目未用列表或学生自定义过程（procedure），不能作为完整正式Create提交。

作业共12题30分，前6题各1分，Q5恰选两项；后6题各4分，逐点评分、可接受等价正确写法。题目全部原创，AP-style仅表示练习风格，书面题不是官方FRQ，教师分数不能换算为AP分数。
