本课目标与边界

学生已有表达式、Boolean、IF和遍历。今天用简单转换和目标判定练习定义、调用、参数绑定和返回值，解释命名过程如何支持复用与维护，并通过虚构文档卡选择合适库行为。列表遍历会在L22放入学生开发的过程，本课先把调用机制教清楚。无递归、全局变量依赖、列表别名或通过参数修改列表的例子。

Session Helpers项目

两个契约：toHours(minutes)接受0至180的数值分钟并返回十进制小时；reachedGoal(minutes,goal)接受0至180的两个数值分钟并返回minutes ≥ goal的Boolean值。两个过程内部不DISPLAY，由调用者选择存储和输出；所有需要的数据通过参数显式传入。测试用整数分钟，但返回小时可以是小数。

PROCEDURE toHours(minutes)
{
  RETURN(minutes / 60)
}
PROCEDURE reachedGoal(minutes, goal)
{
  RETURN(minutes ≥ goal)

参数、控制流与抽象解释

定义中的minutes、goal是形参名称；调用reachedGoal(45,30)中的45、30是实参值，按位置绑定。实参可以由表达式或调用者变量先求值获得。本实验室过程变量为局部，需要的数据显式传参；避免以调用者恰好有同名变量解释参数得到值。RETURN把一个值和控制流带回调用点，调用者继续；DISPLAY向输出发送值，不等于把值返回给调用者。

早返回示例中的RETURN(8)后面DISPLAY(99)不执行，但调用者result←example()+2仍能得到10。没有RETURN的过程可以只执行输出动作；不要擅自给它规定某编程语言的隐含数值返回值。库的文档可以说明参数、顺序、单位、返回类型、前提和输出影响。调用者不必看实现细节，但仍需判断文档是否满足需求并测试。

有效抽象解释应是“同一个目标比较逻辑集中在一个过程，三个功能调用它；以后保持相同契约的内部改进只需改一处”，不能只说“程序更简单”或“肯定更快”。如果修改承诺的行为、返回类型或参数，调用者可能也必须改变。

误区、支持与延伸

  • 写下PROCEDURE就执行：用定义卡与调用卡分开，只有遇到调用才进入体。
  • 实参/形参只是术语：要求画45→minutes和30→goal的绑定线。
  • DISPLAY代替RETURN：让调用者把结果再加2，检查是否真的得到数值。
  • RETURN结束整个程序：回到调用点继续追踪下一条语句。
  • 参数存在却仍硬编码目标：用60/90测试捕获。
  • 有库就无须文档和测试：让学生比较只输出与返回数值两个文档，说明选择理由。

支持：提供完整契约和空白过程框架，让学生填写返回表达式与调用，不直接给全部成品。延伸可用IF在两个路径返回不同消息，但不要扩展递归。最后L22将由学生把FOR EACH计数放到新过程，今天不代写该完整作品。

作业和出口

12题/30教师分，Q5恰选2；书面题各4个独立点。两个编程题至少7行，保持花括号单独成行。出口：实参120；RETURN回调用者而DISPLAY产生输出；举出一个具体API细节。若第二项不清晰，不能仅凭会写公式判定掌握调用机制。
