Read the model carefully

This graph is one connected network, not a complete picture of the Internet. The Internet connects many networks through shared open protocols. The Web is one service that uses the Internet.

Find evidence

  1. Predict the number of connections used from S to T.
  2. Trace S to T, then B to C. Identify an intermediate device.
  3. Explain what the lines represent and what this simplified model leaves out.

The model chooses a route with the fewest connections using breadth-first search. Equal choices use alphabetically sorted neighbours. Real routing considers more information; the fewest hops need not give the lowest latency.

Bandwidth is a maximum data-transfer capacity per unit time. It is different from latency, the time for data to travel. Neither is measured by this diagram.

Send a message in pieces

This toy format uses 3 characters per packet payload and a sequence identifier. Real packets carry bytes and protocol headers.

The missing-packet example omits ID 3 when possible. Retry sends only IDs not yet received; an application may implement similar reliability logic.

Complete message

    Investigate ordering and reliability
    For the default message, send 4,2,1,3. Then try 4,2,1 (loss) and 4,2,2,1,3 (duplicate). Explain why arrival order alone cannot reconstruct the original message and why retransmission needs a way to identify missing data.
    TCP provides a reliable, ordered byte stream; IP alone does not guarantee delivery or order. UDP does not itself supply TCP's retransmission and ordering features. This simplified activity demonstrates sequence tracking and retry, not a complete TCP implementation.

    Redundancy has limits
    Run three tests
    1. Fail A–C. Record the new route and explain why S can still reach T.
    2. Restore the network. Fail S–A and S–B. Explain why other working connections cannot rescue this endpoint.
    3. Find another pair of failures that disconnects S from T. Restore one and test whether service returns.
    Fault tolerance is the ability to keep functioning when a component fails. Alternate paths can improve it. A redundant system can still fail if enough components fail or a critical endpoint becomes disconnected.
    This activity disables connections only. It assumes all devices, software, power and remaining links continue working. Conclusions should be limited to this model.

    Compare three conditions
    Default jobs [6,4,3,3], setup 2, overhead 0: test 1, 2 and 4 processors. Explain why the completion times are 18, 11 and 8, and why four processors do not make the whole program four times faster.
    Load small jobs [1,1,1,1], setup 2, two processors and overhead 6. Compare time 10 with sequential baseline 6. Explain when the coordination cost outweighs parallel savings.
    Scheduling rule: consider jobs in listed order and assign each to the earliest available processor, breaking ties by the lowest processor number. It is a simple greedy schedule, not a claim of global optimality. Jobs are independent and cannot be split.
    Parallel computing performs work simultaneously; distributed computing uses multiple networked devices. These ideas can overlap. This diagram models a schedule and does not simulate a distributed network.
