Study Session Analyzer / 章末项目
Complete the project starter with your own implementation of countGoals(sessions, goal). The list stores valid study minutes (whole numbers 0–180); goal is a whole number in 0–180.
  1. Inside the procedure, initialise a local counter, traverse sessions, and increase the counter for each minutes ≥ goal.
  2. Return the count. The main program displays it, then displays "On track" for a count of at least 2, otherwise "Try again".
  3. Test [20,30,45,10] at goal 30 and 50; [29,30,31] at 30; [0,0] at 30. Extension: test an empty list.
  4. Explain why a list handles changing numbers of sessions and why the parameter makes the procedure reusable.

    Make two different claims carefully
    In AP CSP, polynomial growth is treated as reasonable time; exponential or factorial growth is treated as unreasonable time. That classification does not guarantee a particular program will be fast on a particular computer.
    An undecidable problem has no algorithm that always returns the correct yes/no answer for every input. It is a different limitation from an existing algorithm taking too much time. A heuristic may help with some instances but does not create a universal decision algorithm.
    

    Language model and teaching boundaries / 使用说明
    The programming workspace supports flat lists, 1-based indexing, APPEND, INSERT, REMOVE, LENGTH(list), FOR EACH, procedures with positional parameters, RETURN, and the Chapter 3 expression/control subset. Procedures use separate local variables; data is passed explicitly. Lists are copied on assignment and on entry/return in this teaching model. Do not rely on mutating a parameter to change the caller's list.
    Keep the list being traversed unchanged; construct a separate result list. INSERT uses an existing valid index 1 through LENGTH(list); APPEND adds at the end, including to an empty list. Recursion, nested lists and global-variable access from a procedure are outside this lab subset. CONCAT and SUBSTRING remain explicitly supplied teaching procedures; LENGTH here requires a list.
    The tool stops at 5,000 visible steps, limits lists to 100 elements and uses finite browser numbers. These are tool limits, not AP rules. DISPLAY values appear on separate lines for readability. Editing source or inputs resets execution; predictions remain. Save code and work records before closing the page.
