Lesson 04 · Test & improve

Requirement: integer ticket count 1–50; price 12 per ticket; fee 3 per order. Output the total. Work from your own solution before opening the completed example.

  1. Test ticket counts 1, 2 and 50. Record the expected total before running, then the actual result and pass/fail.
  2. Load “Find the fee bug”. Find an input that reveals the defect and explain why testing only 1 ticket misses it.
  3. Repair the formula, rerun all tests, and record the feedback that prompted a change.

Supported syntax and model / 支持范围

This is an instructional subset, not a full implementation of AP pseudocode. It supports variables, assignment, numeric + - * /, parentheses, numeric INPUT(), and DISPLAY(expression). Double-quoted strings can be assigned or displayed, such as DISPLAY("Total"). Variable names are case-sensitive; whole-line comments begin with //.

No IF, loops, procedures, lists, comparisons, MOD, or string concatenation are implemented here. These belong to later lessons. Unsupported syntax produces a message. A program may run successfully and still give a logically wrong result; check it against the requirements.

The input queue is a classroom substitute for user input. It does not enforce the ticket project's 1–50 integer rule. Invalid test inputs need a separate requirement and validation code, which this chapter has not yet taught. Each DISPLAY appears on its own line for readability; AP reference-sheet DISPLAY normally follows a value with a space.

Calculations use the browser's finite numeric representation. Use small numbers for these exercises; the lab does not model the AP reference sheet's integer capacity. Your code and prediction stay in this page only; use “Save my code” before closing or reloading.
