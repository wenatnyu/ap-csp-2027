Purpose & Scope

以可检验的虚构社区地图任务解释隐私与安全。学生应能把个人信息、推断、授权访问、MFA、加密、证书和常见风险分别说明；不教授具体攻击流程，不以工具颜色代替论证。

Curriculum Alignment

  • Topic 5.6 Safe Computing, IOC-2.A：A.1–15 涵盖个人信息、搜索/浏览/位置历史、组合推断、服务收益、传播与难以删除的风险。
  • IOC-2.B：B.1–4 身份验证、强密码、不同类别的 MFA 与分层保护；B.5 对称与公钥加密；B.6 CA、数字证书与密钥所有权的信任模型；B.7–11 扫描、病毒/恶意软件、更新与权限检查。
  • IOC-2.C：C.1–7 钓鱼、按键记录、公共网络暴露、未经授权的无线接入点、伪装链接/附件和不可信下载。CED 印刷页121–125 / PDF页128–132。

Lab Contract & Teacher Reference

进入 Security 工作区。它是概念模型，不执行真实加密，不接受真实密码，不收集姓名、邮箱或定位值。字段控件只选择字段名称。Community Shade Map 为虚构社区案例，目标仅是按 North/South 汇总遮阴需求。

  1. 55–60：先预测必要字段，再选择。教师参考：zone 用于分组、shadeRating 用于需求度量；name、email、exactGPS 对当前目标非必要。
  2. 60–66：比较 raw / aggregated 的定性风险信息；记录汇总减少个体细节暴露，以及小群体、外部数据链接或采样偏差仍可能造成问题。界面不是现实风险概率估计。
  3. 66–71：分类 password、PIN、verified phone、fingerprint。前两者同属 know；手机步骤表示经验证的 have，指纹属于 are。至少两个不同类别才是本课 MFA 判据。
  4. 71–76：给 Blake 发送机密信息，选择 Blake 公钥加密、Blake 私钥解密；对称模型使用双方共享的同一秘密密钥。数学算法与签名不在本课范围。
  5. 76–80：提交三句建议：目的所需字段、具体防护及其作用、仍剩风险，并说明一条可疑请求的独立核验路径。保留预测与观察差异。

Teaching Decisions & Differentiation

不要把 PII 的定义缩窄为一个字段能够唯一定位某人。不要把聚合写成匿名化保证；本课强调联系其他数据后仍可能推断。认证回答“如何证明身份”，权限回答“获准做什么”，加密回答“如何保护内容不被无权者读取”，三者不能互相替代。

公钥图只画接收者 Blake 的一对密钥；发送者不需要知道 Blake 私钥。CA 是通过信任模型验证密钥所有权，而非审核每句话真实性。密码与 PIN 不构成不同类别；输入手机号文本不等于证明占有手机。

例子全部合成，不猜测或讨论具体学生的个人经历。钓鱼练习只有不可点击的虚构文本；不要让学生打开可疑链接、下载攻击文件、提交密码、收集按键或搭建 rogue access point。所有公共 Wi-Fi 都是恶意网络的说法不成立。

支架：用“risk → measure → remaining limit”三格句型；较熟练学生比较针对相同目的的两种防护方案并解释权衡，而不是增加攻击细节。第16–20页要留下学生原始判断，不能仅抄模型反馈。

Assessment

所有课堂题目、作业与数据情境均原创。作业12题、30分、约40分钟；Q1–Q6为选择题，每题1分，其中Q5恰好选两项且全对、无额外选项才得分；Q7–Q12每题4分，四个独立评分点。可接受有证据且满足条件的等价解释，不把个人伦理立场是否与教师一致当作评分标准。本章调查是课堂练习项目，不是正式 Create Performance Task，也不声称属于官方 FRQ。

退出题：去掉名字仍可能因数据组合出现隐私推断；给 Blake 的保密消息用 Blake 公钥加密；加密连接不证明请求诚实。若密钥角色错，要求重画接收者的一对密钥；若信任边界错，分别写出“通道保护”和“内容判断”的证据。
