Before the official task · 正式任务开始前

1. Prepare the skills, then start a new task

This page is a preparation lesson. Use earlier practice to identify skills you still need, then begin a new program for the official Create task. Do not submit an earlier practice task, a curriculum sample or a renamed copy as your official work.

College Board requires at least nine hours of class time for completing and submitting the task. Our six 90-minute sessions reserve that time for the official work; this rules lesson and technical practice do not use that allocation. Written-response practice is scheduled separately in comprehensive review.

Read the official Student Handouts: preparation and task requirements. The current exam overview confirms the nine-hour allocation.

教师支持：先结束旧练习、反馈与工具演练，再明确宣布正式任务开始。学生可迁移知识与一般技能，但不能把旧练习作品改名提交。新任务的选题和实现由学生负责；程序部分是否采用官方允许的同伴协作，可在开始前说明。六次90分钟是本课程安排，不是“官方规定必须分六次”。

2. One program, three different components

Upload the program PDF and video to their respective components. For the PPR, insert the required code images into the Digital Portfolio fields. Each component needs its own final submission and originality attestation; saving a draft is not the same as submitting it as final.

Official student submission steps · Who creates the PPR?

教师支持：三个交付物不能互相替代：视频不是代码文件，PPR不是整份代码PDF，也不是提前写好的考试回答。本网页和自查结果不会上传到官方平台；学生必须在官方平台逐项完成提交。

3. Connect program elements to a purpose

Your program needs input and related output, a collection whose storage and use manage complexity, and a student-developed procedure with a meaningful parameter and a call. The selected procedure’s body must include sequencing, selection and iteration. Built-in commands or an event handler alone do not replace that procedure.

Collection · 集合抽象

Ask yourself: what becomes harder if the collection is removed or its size changes? A list added only to satisfy a label is not a useful explanation of complexity.

Procedure · 过程抽象

Ask yourself: what does this procedure contribute, how does its parameter affect the result or action, and where does the program call it? Include a return type when needed.

Check the exact requirements in Student Handouts, Components A and C.

教师支持：图只解释“调用、参数、过程体”的关系，不提供可提交代码或固定项目方案。正式阶段由学生识别自己程序中的证据；教师不能代选具体过程或告诉学生如何改写才能满足要求。课程练习阶段可充分练习这些一般概念。

4. Keep attribution in the PDF; keep the PPR clean

Acknowledge borrowed code, media, data and AI assistance in the full program submission. Use code comments when supported; otherwise add the acknowledgments in the document used to produce the code PDF.

The PPR needs procedure and call evidence, plus storage and use of the same collection. Select code you helped develop during the official task. Do not ask a partner, teacher or AI tool to choose your screenshots or assemble your PPR.

Capture readable text at 10-point size or larger; 12-point is preferable. Do not shrink the code and enlarge a blurry image later. Inspect the PPR document produced by the Portfolio, not just the original image. No comments or course explanations belong anywhere on the PPR.

Official PPR image and readability tips · Contribution and acknowledgment rules · Plagiarism, AI and individual components

教师支持：保留带来源说明的完整代码版本，再由学生独立形成不含注释的PPR截图。不能在PPR旁边补“这是循环”等课程说明，也不能借检查清晰度代选更好的片段。仅有复制、引用或理解别人写的片段，不等于自己积极参与了开发；应按官方贡献与署名规则处理。PPR违规可能导致Create及相关书面作答零分，须在准备阶段讲清。

5. Show the program running

Make the video independently. It must demonstrate input, an aspect of functionality and output; keep it within one minute and 30 MB. Use an accepted format: .webm, .mp4, .wmv, .avi or .mov. Exclude identifying information and voice narration; text captions are allowed.

See Student Handouts, Component B for the complete video directions.

教师支持：准备阶段用旧练习或无关测试画面练习录屏操作；正式视频由学生独立决定展示内容并制作。这里不提供某个正式项目的镜头脚本。先测试系统录屏权限、文件大小和播放器，避免把正式课堂时间耗在工具设置上。

6. Rehearse the tools before the clock starts

Use a practice file to complete this technical rehearsal. Keep it clearly separate from the new official task.

Export and reopen

Create a practice code PDF, reopen the saved file and inspect every page. Check that text, indentation and the edges of blocks remain visible. Keep a working copy and a backup.

Record and replay

Save a short practice recording, check its duration and file size, and replay it in the intended player. Learn how to capture only the intended window.

Verify access

Sign in to the AP Digital Portfolio using your College Board account. Confirm that the correct CSP class and component areas are available, and that your school has included you in its exam order. Resolve access or registration problems with your teacher or coordinator.

Understand final submission

Read the current screen instructions and attestations in advance. Do not press Submit Final for a practice file. During the actual task, reopen and check each intended submission before making it final.

Keep official task files private. Do not post program code, screenshots or video publicly, including in this course’s public GitHub repository. The current Student User Guide explains the risk of others copying publicly shared task work.

The official submission instructions explain access, component uploads, PPR images and final submission. Use the current Student User Guide linked there for interface details.

教师支持：技术演练在正式九小时之外安排，不要求把练习文件正式提交到官方平台。记录设备权限、导出与账号问题并先解决；账号登录由学生本人完成，不收集密码。界面可能更新，课堂截图不能代替官方当前页面指示。

7. Know which help is permitted

Program collaboration

Permitted peers can discuss ideas and develop, debug and test the program together. You must participate actively. Acknowledge code you did not help create, and do not use those segments as your own PPR evidence.

Official collaboration examples and attribution

Individual artifacts

Make your video and PPR yourself. Program collaboration does not authorize a partner to select, assemble or revise these individual components. Written responses are also independent work on exam day.

Official boundary between program and individual work

Teacher and coordinator

They can clarify directions and address technical or collaboration-access problems. During the official task, do not ask them to design, debug, test or improve your program, choose your PPR evidence, or judge which implementation will earn credit.

Student Handouts: completing the task

AI is supplementary

The 2026–27 policy permits AI support for coding concepts, development and debugging. You and any permitted partner must actively develop the required input, output, collection, procedure and calls. Review, test, understand and acknowledge any AI-assisted code. This permission does not extend to having AI create your video or PPR, or answer your exam-day written responses.

8. Six preparation checks

Decide true or false before expanding each answer. These are original classroom rule checks, not official AP questions, a rubric or approval of anyone’s submission.

1. Renaming my completed practice project makes it a new official task.

False. A new title does not change the work’s origin. Use what you learned to develop new official work; do not submit the earlier practice task.

2. We may collaborate on program debugging, then create our videos and PPRs separately.

True, within the collaboration rules. Each student must be actively involved in program development and handle attribution correctly. The individual components must remain independently created.

3. Removing comments from PPR images means I should also remove source acknowledgments from the program PDF.

False. Preserve required acknowledgments in the full code submission. The PPR has a separate restriction on comments and course material.

4. Merely naming an unused parameter satisfies the requirement that it affect procedure functionality.

False. The parameter must actually influence the procedure’s behavior. A name alone provides no such relationship.

5. I should check input, functionality and output, as well as format, duration, size and anonymity, before finalizing my video.

True. The demonstration and the file requirements both matter. Replaying the exported file can reveal a missing interaction, unreadable output or unintended identifying information.

6. Asking my teacher to choose my best PPR screenshots is only a technical readability check.

False. Choosing evidence is part of creating the PPR and is your responsibility. Technical guidance must not become selection or improvement of your submission’s content.

教师支持：先让学生说依据，再展开答案；错题用于安排准备阶段的补充讲解。完成自查不代表作品合格认证，也不代表已正式提交。正式作品不交给教师、同伴或本网站代选证据、代写回答；综合复习会另行安排原创书面题训练。
